1. Explica el flujo completo desde que un admin hace login hasta que puede agregar un plato. Menciona cada archivo que participa y qué hace cada uno.
Respuesta: 
El admin manda POST `/auth/login` con sus credenciales. Pasa por el router (`auth.routes.js`) hacia el controlador (`auth.controller.js`). Este llama al service (`auth.service.js`) donde se busca al usuario, se compara su clave encriptada usando `bcrypt.compare` y si coinciden, se genera un JWT firmado (`jwt.sign()`). El controlador le devuelve ese token al admin. 
Para agregar un plato, el admin envía un POST a `/menu` incluyendo el token en el header `Authorization`. El middleware (`verifyToken.js`) lo intercepta, extrae el token y lo valida con la clave secreta. Como el token es válido, se llama a `next()` y la petición llega al `menu.controller.js`, que procesa los datos y llama al `plato.service.js` para guardarlo en la base de datos usando Mongoose (`plato.model.js`).

2. ¿Por qué bcrypt.compare() puede verificar la contraseña si el hash es irreversible? ¿Qué está haciendo internamente?
Respuesta: 
Porque bcrypt.compare() en realidad no decodifica el hash guardado de vuelta a texto plano. Lo que hace es tomar la contraseña nueva que acaba de ingresar el usuario, le aplica internamente el *mismo* algoritmo de encriptación (usando la *salt* original que viene impregnada en el hash) y luego verifica si el nuevo string encriptado resultante es idénticamente igual al string encriptado que estaba guardado en MongoDB.

3. Si alguien roba un token JWT válido, ¿qué puede hacer con él? ¿Qué mecanismo del sistema limita el daño? ¿Qué agregarías para hacerlo más seguro?
Respuesta: 
Si alguien lo roba, en teoría tiene acceso total para hacerse pasar por el administrador y modificar la base de datos (borrar el menú, crear platos, etc.). El primer mecanismo de defensa que limita el daño es que el token tiene una fecha de caducidad (`expiresIn: '24h'`); pasado ese tiempo el token se vuelve basura inservible. Para hacerlo más seguro, se le podría bajar el tiempo de expiración (ej. a 15 minutos) y manejar Refresh Tokens, o agregar listas negras de tokens y verificaciones de dispositivo/IP.
