1. Hace 8 días el restaurante no existía. Hoy tiene base de datos, autenticación, tests y configuración segura. Describe en tus propias palabras qué aprendiste que no sabías al empezar. Sé específico — no digas 'aprendí mucho', di exactamente qué.

Respuesta:
Aprendí que un backend profesional no es solo un montón de funciones sueltas, sino una arquitectura organizada por capas (MVC).
- Aprendí a conectar Node.js con MongoDB usando Mongoose.
- Aprendí a proteger rutas usando JWT y Middlewares de verificación.
- Aprendí la importancia de las Variables de Entorno (.env) para no subir contraseñas a GitHub.
- Aprendí a escribir tests automáticos con `supertest` para que mi código se verifique solo sin tener que probar todo a mano en Thunder Client.

2. Si mañana tuvieras que agregar una nueva entidad al restaurante — por ejemplo, una tabla de pedidos — ¿qué archivos crearías, en qué orden y por qué ese orden? Describe el proceso sin escribir código.

Respuesta:
Seguiría este orden para construir desde los cimientos hacia afuera:
1. **Modelo (`models/pedido.model.js`)**: Definir qué datos tiene un pedido (platos, total, mesa). Sin modelo no hay base de datos.
2. **Servicio (`services/pedido.service.js`)**: Escribir las funciones para crear, listar o cancelar pedidos. Aquí vive la lógica de negocio.
3. **Controlador (`controllers/pedido.controller.js`)**: Recibir la petición HTTP, validar los datos de entrada y llamar al servicio para responder al cliente.
4. **Rutas (`routes/pedido.routes.js`)**: Definir los endpoints (como POST /pedidos) y decidir cuáles necesitan seguridad mediante middlewares.
5. **Registro de Rutas (`app.js`)**: Conectar el nuevo archivo de rutas a la aplicación global para que empiece a funcionar.
6. **Tests (`test/pedido.test.js`)**: Escribir pruebas para asegurar que los pedidos se crean y consultan correctamente.
